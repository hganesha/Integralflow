Design system v1.0 · Financial Crime Experience Platform
An instrument, not a dashboard.

Warm porcelain and graphite surfaces, restrained emerald, ochre, coral and slate-blue. Banks keep fixed positions; segments read like keys on an analog instrument. Colour never carries meaning alone, and nothing animates unless a recorded event happened.

Tokens: assets/tokens.css · tokens.json · Components: assets/components.css · Written guidance: STYLE-GUIDE.md

Principles in the pixels

Do name the dimension of every state — PublicationDraft — so a green chip is never ambiguous.
Don’t use a green toggle to mean “working”. A configured switch is not a successful execution or an approval (spec §3.4).
Do show uncertainty in shape: Assertion vs Verified fact.
Don’t show an uncalibrated score as a percentage, or collapse readiness into a single %.
Do render missing data as a hatched, labelled gap with its code (CONTEXT_MISSING).
Don’t animate progress that isn’t backed by an event, or show success before server confirmation.

Accessibility (WCAG 2.2 AA)

Keyboard
  • Banks & keys: arrow-key grid navigation, Enter selects
  • Tabs: ←/→ roving tabindex
  • Sheets: focus trap, Esc closes, focus returns
  • Graph nodes focusable with full aria-labels
Non-visual alternatives
  • Every graph has a Table view and an SVG <desc>
  • Status = tone + glyph + text
  • Live regions for interrupts and “new items”
  • Reduced motion and high-contrast token overrides
