# Azure acceptance setup

The implementation is ready for an isolated Azure acceptance environment. Live Azure execution remains to be verified in the user's subscription. Use the merged Azure foundation/runtime deployment workflow and its private runtime inputs; source evaluation adds one manual Container Apps job and a dedicated controller identity.

1. Build and push `Dockerfile.workbench-evaluator` to the existing private registry. Resolve the pushed image to its `@sha256:` digest. Build/push the updated platform image and apply migrations 054/055 and the grant matrix through the migration job.
2. Deploy `deploy/azure/workbench-job.bicep` in the existing foundation resource group. Supply `name`, `environmentName`, `pullIdentityId`, `registryHost`, digest-pinned `image` and `storageAccountName`. The storage account must be reachable by Container Apps and the control plane. The deployment creates a private `workbench-evaluations` container.
3. Copy the deployment's `workbench` output object into the existing private runtime inputs. It contains the job ID, image digest, storage account/container and controller identity ID/client ID. Redeploy the runtime using the existing launcher recipe. Only the control API receives this identity and evaluator configuration. Retain the existing workload identity, model and telemetry settings.
4. Configure an active model profile/provider through Administration using the Azure model endpoint and credential reference. The provider secret belongs only to the gateway. Verify the configured model endpoint, collector, stores, runtime journal and worker replicas on Health before authoring tests.
5. Start with a one-case Python skill evaluation. Edit/save, evaluate, inspect source and dataset digests, then have a different reviewer approve/publish. Export and reload the published source.
6. Test an agent with one attached published skill and one fixture case using a low token limit and a small evaluation reservation. Inspect the real model response, tokens, available cost, tool receipt digest and collector trace. Verify no platform/model credentials or network access are available inside edited source.
7. Stop admission in drain mode, verify new run admission is refused, and resume with a reason. In this isolated environment, separately test cancel mode against queued and running invocations. Verify fence advancement and cancellation acknowledgment.
8. Stop a worker/collector or remove a test identity binding and confirm health changes to stale/degraded/unavailable with no credential leakage. Restore the dependency and verify recovery. Test evaluation cancellation, a schema mismatch and an expired worker lease.

The controller has job start/read authority scoped to the evaluation job, blob data authority scoped to the private container, and storage delegation-key authority on the account. It receives no job secrets/list-secrets/exec authority. The job has only the existing registry pull identity. Signed URLs authorize one input read and one output create/write for ten minutes. The sandbox child drops privileges and cannot open sockets, including access to a managed identity endpoint.

For cleanup, delete the disposable job and controller/role assignments after test evidence is exported; remove leftover evaluation blobs in the dedicated container. Retain immutable review/evaluation records as required by the test environment's data lifecycle. Running/admitted plans retain their previous pins until the normal release deployment.

Authoritative API references: [Container Apps job start](https://learn.microsoft.com/en-us/rest/api/resource-manager/containerapps/jobs/start?view=rest-resource-manager-containerapps-2025-07-01), [manual jobs](https://learn.microsoft.com/en-us/azure/container-apps/jobs), [Blob roles](https://learn.microsoft.com/en-us/azure/role-based-access-control/built-in-roles/storage), [scoped SAS permissions](https://learn.microsoft.com/en-us/rest/api/storageservices/create-service-sas).
