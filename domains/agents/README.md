# Business agents

The ten agents of the agentic KYC and KYB flows ([docs/implementation/agent-roster.md](../../docs/implementation/agent-roster.md)).
One YAML per agent; `roster.json` and the roster test package are generated:

```sh
node scripts/sync-agent-roster.mjs          # roster.json + packages/contracts/test-fixtures/agent-roster
node scripts/sync-agent-roster.mjs --check  # CI
make compile                                # artifacts/agent-roster.plan.json (harnessc checks every profile)
```

Each file states the agent's mandate (imported agents take theirs from the library profile), its
required skills (deterministic skill nodes that run as the agent), optional skills (read-only, chosen
by its loop), read-only tools, model tier, completion criteria (the library task, narrowed to its own
skills, or authored), its agent-specific output fields and a worked example. An imported agent may
narrow its library profile; any skill outside the library profile must be listed in
`source.additions` with a reason.

An agent may also declare `reads:`, the record types its review reads beside its skills' results
(optional selectors: a missing type is an absence the agent reports). The identity agent reads the
document agent's `ExtractedAssertion` records and the `DocumentPage` text next to the identity and
registry records. In output fields, `enum: CATALOG_DOCUMENT_TYPES` is replaced with the document field
catalog's type ids. The flows that use these agents are generated by `scripts/sync-agentic-flows.ts`
([agentic-flows.md](../../docs/implementation/agentic-flows.md)).
